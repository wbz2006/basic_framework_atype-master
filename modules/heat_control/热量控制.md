# 热量控制模块

## 数据来源

底盘应用从裁判系统回传结构体读取数据，并以 `HEAT_CONTROL_DATA_TOPIC` 主题每 100 ms 发布一次：

- `current_heat`：`referee_info_t.PowerHeatData.shooter_17mm_1_barrel_heat`，当前枪管热量 Q1；
- `heat_limit`：`referee_info_t.GameRobotState.shooter_barrel_heat_limit`，热量上限 Q0；
- `cooling_rate`：`referee_info_t.GameRobotState.shooter_barrel_cooling_value`，每秒冷却值。
- `bullet_heat`：由 `modules/heat_control/heat_control.h` 中的 `HEAT_CONTROL_BULLET_HEAT` 统一配置，当前项目为 `2.0f`；修改该宏即可同步应用初始化和算法计算。

热量增量以裁判系统当前配置为准（本项目通过宏配置为每发 2 点），冷却按 10 Hz 结算，因此模块只在 100 ms 结算边界更新射速。

## 使用方式

应用层初始化一个 `HeatControlInstance` 并调用 `HeatControlInit()`。连续发射时调用：

```c
shoot_cmd_send.shoot_rate = HeatControlCalculate(&heat_control, 1);
```

非连续发射时传入 0，模块会复位输出并返回 0。模块会自行从消息中心读取最新裁判数据，不再调用数据更新函数。

每个 100 ms 结算点根据下一周期的热量预算计算射频：

```text
shoot_rate = (Q0 - 3 * bullet_heat - Q1 + cooling_rate * 0.1)
             / (bullet_heat * 0.1)
```

热量充裕时结果会被裁剪为最大射频；接近上限时逐步降低，并预留三发热量应对反馈和机构延迟。

## 安全策略

- 当前热量达到或超过上限时，目标射速为 0；
- 未收到有效数据、冷却值为负或参数未初始化时，目标射速为 0；冷却值为 0 仍按合法数据处理；
- 输出射速限制在 `[0, max_shoot_rate]`；
- 计算使用 `Q0-Q1` 作为可用热量，避免将当前热量误当成剩余热量；
- 默认预留三发（当前配置为 6 点）热量，不将热量顶到裁判上限。
